# 문제별 재사용 지도
완성 앱 하나를 모든 문제에 억지로 맞추지 않는다. 먼저 필수 입력 → 판정 → 출력 한 줄을 적고 해당 부품만 쓴다.

| 문제 유형 | 재사용 | 현장에서 바꿀 것 | 최소 확인 |
|---|---|---|---|
| 요청/재고/작업 관리 | CRUD·상태·검색·저장·목록 | 필드·허용 상태·상태 전이·중복 기준 | 등록→변경→재시작 후 유지 |
| CSV 정리/비교 | modules/table.mjs의 parseCSV/toCSV | 헤더 매핑·타입 변환·누락/중복 정책 | 따옴표·쉼표·줄바꿈·누락 열 |
| 우선순위/추천 | rankRows·표 출력 | 가중치·유효 범위·동점 기준·근거 표시 | 손계산 예제와 일치 |
| 운영 대시보드 | summarize·요약 UI·필터 | 분모·단위·기간·지표 의미 | 빈 데이터와 필터 적용 범위 |
| 문서/상품 초안 생성 | modules/external.mjs·표시 UI | 제공 API 계약·응답 검증·수정 승인 | 시간 초과·잘못된 JSON·폴백 표시 |
| 데이터 품질 점검 | validateItem·가져오기 검증 | 행별 오류 보고·정상 행 보존 정책 | 잘못된 행이 저장을 일부 오염하지 않음 |

## 30분짜리 변경 연습
1. title/value/status를 품목명/수량/검수상태로 바꾼다.
2. 완료된 항목 수정 금지 규칙을 domain.mjs의 명시적 함수로 작성한다.
3. 동일 품목 중복 입력 정책을 정하고 테스트한다.
4. 브라우저에서 정상·빈 입력·오류·새로고침을 직접 확인한다.
5. 변경 이유와 깨질 조건을 AI 없이 1분 설명한다.

## CSV 연결 예
서버에서 parseCSV(text)로 읽고 각 열을 명시적으로 매핑한다.
Number('')는 0이므로 빈 문자열을 먼저 거부한다. 변환 후 validateItem을 통과시킨다.
CSV 업로드 라우트/버튼은 기본 앱에 연결되어 있지 않다. 필요할 때만 추가한다.
Excel 배포용 toCSV(rows,{spreadsheetSafe:true})는 수식으로 시작하는 셀을 문자열 처리한다.
대용량 CSV는 이 인메모리 파서를 쓰지 말고 제한/스트리밍을 검토한다.

## 점수 예
rankRows(rows,{quality:2,cost:-1})는 quality*2-cost 순서다.
단위가 다르면 사전에 정규화하고, 가중치 선정 이유·민감도·동점 처리 방식을 설명한다.
이 함수는 객관적인 최적해가 아니라 합의한 기준의 결정론적 정렬이다.

## 외부 AI 예
서버에서만 fetchJSON을 호출하고 환경 제공 API 계약을 따른다.
키/모델/SDK를 임의로 가정하지 않는다. source가 fallback이면 UI에 '데모 결과'를 표시한다.
검색 기반 생성이 필요하면 출처와 근거 없는 답변 처리부터 정한다. 벡터 DB부터 설치하지 않는다.
