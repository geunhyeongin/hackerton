# 첫 10분
1. 현장 안내의 허용 스택·사전 코드 반입·외부 네트워크·키·제출 파일·구현 마감·이해도 평가 시간을 확인한다.
2. pwd, ls, README, 기존 AGENTS.md와 공개 테스트를 먼저 읽는다. 안내문은 고정 제약과 미확인 업무 가정을 나누어 읽는다. 모든 내용을 의심하며 인터뷰를 길게 끌지 않는다.
3. node scripts/doctor.mjs로 도구 버전을 확인한다. API 키를 화면/로그에 출력하지 않는다.
4. 앱이 이미 있으면 기존 실행 명령을 따른다. 없고 Node가 허용되면 bootstrap으로 web-app을 복사한다.
5. node server.mjs 실행 후 3000 포트 미리보기를 연다. 서버 안의 localhost는 참가자 PC의 localhost와 다르다.
6. 빈 목록 → 등록 → 새로고침 후 유지 → 상태 변경을 확인한다.
7. 핵심 사용자·최근 실제 사례·예외·성공 기준을 확인한다. 기능 체크리스트가 고정이면 필수 항목부터 추적표에 모두 옮긴다.
8. 성공 기준 1~3개와 필수 요구사항을 기록하고, 전체 목록 중 하나의 세로 흐름을 먼저 끝낸다.
9. 플러그인 설치가 3분 이상 막히면 기본 스킬/프롬프트로 진행한다. 설치 자체는 평가 산출물이 아니다.

## 시간은 현장 값으로
- 전체 응시 종료와 구현 제출 마감은 별개다. AGENTS.md의 빈칸에 실제 공지를 기록한다.
- 계획 예시: 가용 구현 시간의 10% 탐색/합의, 55% 핵심 구현, 20% 예외/브라우저 검증, 15% 제출/설명 연습.
- 이 비율과 설치 3분은 준비용 권장값이며 공식 규칙이 아니다.
