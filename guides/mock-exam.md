# AI 없이 보는 15분 이해도 시험
먼저 아래 질문에 답하고 나서 마지막 채점 기준을 본다.
1. 등록 버튼에서 파일 저장까지 흐름을 파일/함수 이름으로 설명하라.
2. 브라우저 min=0이 있는데 왜 서버도 음수를 거부하는가?
3. 동시에 등록한 두 항목 중 하나가 사라지는 문제를 이 코드는 어떻게 줄이는가?
4. 손상된 저장 파일이 발견되면 빈 배열로 자동 초기화하면 안 되는 이유는?
5. 이 앱의 가장 큰 운영상 약점 2개를 '약점 → 파급 → 개선'으로 설명하라.

## 직접 수정 과제 (추가 15분)
'완료 항목은 value 변경 불가, 대기로 되돌린 뒤 수정 가능' 규칙을 추가하라.
규칙을 순수 함수로 분리하고 정상/거부/복구 후 수정 테스트를 작성하라.
UI에 값 편집이 없으므로 API 테스트로 검증하거나 필요하면 편집 화면을 추가한다.
왜 서버 규칙이 필요한지 설명하라.

## 채점 기준 (5문항 × 4점)
각 문항: 현재 동작 1점, 코드 근거 1점, 깨질 조건 1점, 검증/개선 1점.
1: app.js→POST→body/validateItem→store.change→파일 교체→refresh.
2: 직접 API 요청은 HTML 제약을 우회함. 음수 요청 400으로 검증.
3: 읽기-수정-저장을 큐로 직렬화. 다중 프로세스/서버에는 미적용.
4: 손상을 빈 데이터로 취급하면 다음 저장에서 기존 데이터 유실. 오류·백업·복구가 필요.
5: 인증 없음, 단일 JSON/프로세스, 가져오기 중복 등 실제 한계와 영향·대안을 연결.
준비용 자가 기준: 16점 이상 + 수정 과제 완료. 공식 평가 기준이 아니다.
