# 내가 설명할 수 있는 코드
## 읽는 순서 (20분)
1. public/index.html: 어떤 입력과 출력이 보이는가?
2. public/app.js: 등록 버튼 → fetch → 화면 갱신. textContent를 쓰는 이유.
3. server.mjs: HTTP 경로와 메서드 → 입력 → 도메인 함수 → 저장 → 응답.
4. domain.mjs: 허용 입력·상태·필터·집계를 직접 손계산.
5. store.mjs: Promise 큐 → 읽기 → 변경 → 임시 파일 → rename.
6. tests/: 정상 입력보다 실패 사례가 무엇을 보장하는지 설명.
7. 선택 모듈은 실제 사용한 것만 읽고, 쓰지 않는 모듈은 설명 대상에 끼워 넣지 않는다.

## 데이터 한 건의 여행
사용자가 제목/값 입력 → app.js가 JSON POST → server가 바디 제한/파싱
→ validateItem이 타입/범위 검사 → UUID 생성 → 큐에서 원자적 파일 교체
→ 201 응답 → 목록/집계 재조회 → textContent로 출력.

## 설계 이유와 한계
- 빌드/패키지 설치 없이 바로 실행: React/DB 학습 시간을 줄인다. 복잡한 UI에는 별도 스택이 나을 수 있다.
- 서버에서 검증: 브라우저 검증은 직접 HTTP 요청으로 우회할 수 있다.
- 단일 큐: 같은 서버 프로세스의 동시 쓰기를 보호한다. 프로세스 두 개는 보호하지 않는다.
- 임시 파일 rename: 쓰다 실패해서 원본 JSON을 절반만 남기는 위험을 줄인다. DB 트랜잭션/백업은 아니다.
- 데이터 파일은 정적 공개 목록에 없다. 인증은 없으므로 실제 다중 사용자 운영 서비스로 공개하지 않는다.
- 새로 가져온 ID를 생성: 가져온 파일의 ID 충돌을 피한다. 동일 파일 재업로드는 중복 데이터를 추가한다.
- PATCH는 허용 필드를 다시 검사한다. 상태 전이 제약은 현재 없다.
- 집계는 전체 데이터 기준이다. 필터된 목록 집계가 요구되면 그 기준을 명시적으로 바꾼다.
- CSV/점수/외부 API 모듈은 선택 도구이며 화면에 자동 연결되지 않는다.

## AI에게 요청할 설명 형식
'사용자 행동 → 함수/파일 → 입력/출력 → 실패 조건 → 검증'으로 설명해줘.
내가 입력을 바꿨을 때 결과를 먼저 예측하게 하고, 틀리면 관련 코드 부분만 설명해줘.
답을 외우게 하지 말고 작은 요구사항 변경을 직접 수행하게 해줘.

## 주석 읽는 기준
직접 만든 스킬의 본문과 설명은 한국어로 작성했다. name·함수·파일 식별자는 기존 영문을 유지한다.
주요 소스의 주석은 역할·입출력·왜 필요한지·현장 수정 위치·한계를 설명한다. 한 줄을 한국어로 반복하는 주석은 줄인다.
기능을 바꾸면 주석도 함께 갱신한다. 주석은 설계 의도를 알려주며, 실제 동작은 코드와 실행 결과로 확인한다.
외부 패키지는 원문과 해시를 보존한다. 영어 원문은 필요한 부분만 AI에게 한국어로 설명하게 할 수 있다.
