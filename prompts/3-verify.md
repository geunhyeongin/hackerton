# 검증 프롬프트 모음

## 교차검증 (새 세션 또는 다른 모델에서)
이 저장소를 처음 보는 리뷰어로서, AGREEMENT.md의 성공 기준과 코드를 대조해라.
1. 성공 기준마다 충족 여부를 실행 결과로 확인한다. 실행하지 않고 판단하지 않는다.
2. 코드의 약점 5개를 지목한다. 각 약점은 "어디서 깨지는가 / 왜 위험한가 / 무엇으로 검증할 것인가" 순서로 쓴다.
3. 장애 시나리오(입력 이상, 외부 호출 실패, 데이터 누락, 빈 값)별로 현재 동작을 확인한다.
4. 문서와 코드가 다른 부분을 찾는다.
코드는 수정하지 말고 보고만 해라.

## 감시용 세션 (옆 탭, 읽기 전용)
이 세션은 코드를 수정하지 않는다. 내가 "현황"이라고 하면 git log와 HANDOFF.md, 현재 시각을 읽고 다음을 답해라.
- 경과 시간 대비 진척률
- 합의된 성공 기준에서 벗어난 작업
- 증거 없이 완료 처리된 항목
- 지금 가장 위험한 것 하나

## 약점 감사 (제출 20분 전)
현재 코드에서 면접관이 물을 만한 질문 6개를 뽑아라. 각 질문마다 "약점 > 파급 > 개선 계획" 3단 답안 초안을 한 줄씩 써라. 답안은 내가 읽고 이해할 수 있는 말로 써라.
